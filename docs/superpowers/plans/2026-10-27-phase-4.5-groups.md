# Phase 4.5: Interchangeable Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner groups interchangeable products into groups like "Drinks · Jaco" or "Pasta · Home". The list then suggests the group, with every option's price per kg / L / roll and the cheapest marked. Complete trip asks which product was bought.

**Architecture:**
- Pure rules live in `src/groups/groupRules.ts`: holds, joining, group need, cheapest option and the hint.
- `src/list/listRules.ts` extends `planList` and `validateTrip` to handle group entries.
- `src/groups/groupRepo.ts` writes the groups, members and people.
- `useUsage` also returns per-group usage, and suppresses the own suggestion of grouped items.
- New routes: `/groups` (a list of groups) and `/groups/[id]` (new or edit).
- The item, Prices, List and Complete trip screens gain the group parts.

**Tech Stack:** The phase 4 stack. No new dependencies.

**Spec:** [docs/superpowers/specs/2026-10-27-interchangeable-groups-design.md](../specs/2026-10-27-interchangeable-groups-design.md) is binding. It also brings in [2026-10-26-grocery-planner-design.md](../specs/2026-10-26-grocery-planner-design.md) 4.1–4.3 and 4.6, and phase 4 as shipped.

## Global Constraints

- **Schema** (PowerSync, in code, no migration):
  - `items` gains `contents_qty` (real) and `contents_unit` (text).
  - New table `people (name, created_at)`.
  - New table `item_groups (kind, person, base_unit, buy_mode, buffer_pct, max_months_cover, est_monthly_usage, active, created_at)`. It's named `item_groups`, not `groups`, to stay clear of the SQL keyword.
  - New table `item_group_members (group_id, item_id)`, indexed on both.
  - `list_entries` gains `group_id` (text).
  - "Home" is a built-in person name, not a row.
- A group's name is `{kind} · {person}`. The pair `(kind, person)` is unique, ignoring case. `base_unit` is `'kg'`, `'L'` or a count word.
- **holds(item, base):**
  - A sold-by-measure item whose `unit === base` holds 1.
  - Otherwise, if `contents_unit === base` and `contents_qty > 0`, it holds `contents_qty`.
  - Otherwise `null`, and the item cannot join.
- **share** = `1 / (number of active groups the item is in)`. That gives a 50/50 split for two groups, with no override.
- **Group need** = Σ `perMonth × holds × share` over members with usage. If none have usage, use the group estimate, else it's "needs data".
- **Group stock** = Σ `(stock ?? 0) × holds × share`.
- **Group toBuy** = `suggestBuy` with the group's buffer and cap. The unit is `base` if it's `kg` or `L`, else `'each'`. Use `sold_by_weight: 0` and `pack_size: null`.
- **Cheapest option** = the lowest `LAST_PRICE_SQL unit_cents / holds`. That price already ignores specials (owner confirmed). Unpriced members are never cheapest.
- **Hint** = `ceil(amount / holds(cheapest))` in the item's own unit, ignoring `pack_size` (owner: "just say number of cans").
- While an item is in any active group, it gets no list suggestion of its own. The group's buy mode, buffer and cap apply, and the item screen captions `Set by {group name} while grouped`.
- Ticked and hand-added entries, item or group, are never touched by Refresh (spec 4.3).
- Money is cents, colours come from the theme, there's one accent per screen (none new), `Link asChild` takes a single style object, and owner commands use `npx.cmd`.

## Review Focus

1. **The drink both partners like:** 10 cans of 0.5 L used, in two groups, gives 2.5 L to each group, never 5 L to both. → Task 1 test `groupNeed splits a shared item 50/50`.
2. **Concentrate versus ready-made:** a 5 L-making concentrate at R45 beats a 1 L juice at R18 (R9 versus R18 per L). → Task 1 test `cheapestOption compares per base unit`.
3. **A grouped item's old list row:** after it joins a group, Refresh removes its unticked suggested row and inserts the group row. A ticked one stays. → Task 2 test `planList replaces a newly grouped item with its group`.
4. **Changing the holds unit of a grouped item** (L → kg) is refused with `Remove it from Drinks · Jaco first`. → Task 1 test `checkGroupUnits refuses a unit that breaks a group`.
5. **Mixed group purchase:** one ticked group row bought as 6 Monster + 4 Red Bull becomes two purchases, and one bad line saves nothing. → Task 2 test `validateTrip keys errors by line and keeps the item per line`.

### Task 1: Group rules

**Files:**
- Create: `src/groups/groupRules.ts`
- Test: `src/groups/groupRules.test.ts`

**Interfaces:**
- Consumes: `suggestBuy` (usage), `parseDecimal` (items), `findDuplicate` pattern (case-insensitive).
- Produces:
  - `type Measurable = { sold_by_weight: number; unit: string; contents_qty: number | null; contents_unit: string | null }`
  - `holds(i: Measurable, base: string): number | null`
  - `groupName(g: { kind: string; person: string }): string`, which returns `'Drinks · Jaco'`.
  - `checkGroupUnits(i: Measurable, groups: { kind: string; person: string; base_unit: string }[]): string | null`. Returns `Remove it from {name} first` for the first group the item can't be measured in, else `null`.
  - `type GroupForm = { kind: string; person: string; baseUnit: string; buyMode: 'monthly' | 'as_needed'; bufferPct: string; maxMonthsCover: string; estMonthlyUsage: string }`
  - `validateGroup(f: GroupForm, others: { id: string; kind: string; person: string }[], selfId?: string): { ok: true; values: {...snake_case columns} } | { ok: false; errors: Partial<Record<keyof GroupForm, string>> }`
    - It uses the same buffer and cap rules and copy as `validateItem`.
    - It adds `Give the group a kind`, `Pick a unit`, and `You already have {name}`.
    - Blank person becomes `Home`.
  - `type Member = { perMonth: number | null; stock: number | null; holds: number; share: number }`
  - `groupNeed(members: Member[], g: { est_monthly_usage: number | null; buffer_pct: number; max_months_cover: number; base_unit: string; buy_mode: string }): { perMonth: number | null; source: 'measured' | 'estimate' | 'none'; stock: number; toBuy: number | null }`. `toBuy` is null for as-needed groups or when there's no need.
  - `cheapestOption<T extends { unitCents: number | null; holds: number }>(options: T[]): (T & { perBase: number | null })[]`. Cheapest first, unpriced last, and it keeps the input order on ties.
  - `hintCount(amount: number, holds: number): number`, which is `Math.ceil(roundQty(amount / holds))`.

- [ ] **Step 1: Write the failing tests:**
  - `holds`:
    - A kg item in a kg group → 1.
    - A can with contents 0.5 L in an L group → 0.5.
    - The same can in a kg group → null.
    - No contents → null.
    - An 18-roll pack in a `roll` group → 18.
  - `groupName` → `'Drinks · Jaco'`.
  - `checkGroupUnits refuses a unit that breaks a group`: contents in kg against "Drinks · Jaco" (L) → `'Remove it from Drinks · Jaco first'`. A matching unit → null.
  - `validateGroup`:
    - A duplicate `drinks`/`jaco` against `Drinks`/`Jaco` → `You already have Drinks · Jaco`.
    - Blank kind → `Give the group a kind`.
    - Blank person → `Home`.
    - Blank base unit → `Pick a unit`.
  - `groupNeed splits a shared item 50/50`: one member with perMonth 10 (cans), holds 0.5, share 0.5, and one member with perMonth 4, holds 0.5, share 1 → perMonth `4.5`.
  - `groupNeed falls back to the estimate, then needs data`. As-needed groups give `toBuy` null.
  - `groupNeed counts never-counted stock as 0 and buys`: base L, need 4.5, stock 1, buffer 10 → toBuy `4` (4.95 − 1 = 3.95, rounded up to 0.1).
  - `cheapestOption compares per base unit`: juice `{unitCents: 1800, holds: 1}` and concentrate `{4500, 5}` → concentrate first with perBase 900. An unpriced option comes last with perBase null.
  - `hintCount`: `(6, 0.5)` → 12, `(6.1, 0.5)` → 13, `(30, 18)` → 2.

### Task 3: Schema, repositories and usage

**Files:**

**Interfaces:**
- **Item form:**
  - `ItemForm` gains `contentsQty: string` and `contentsUnit: string` (default `''`).
  - `ItemValues` gains `contents_qty: number | null` and `contents_unit: string | null`. Both are null for sold-by-measure items, or when the qty is blank.
  - Errors: `Holds must be blank or more than 0`, and `Pick what it holds` (qty set but no unit).
  - `itemToForm` and `FIELDS` carry them.
- **`groupRepo.ts`:**
  - `GROUPS_SQL` (active groups with member count, ordered by kind then person).
  - `PEOPLE_SQL`.
  - `createGroup(values): Promise<string>`, `updateGroup(id, values)`, `setGroupActive(id, active)`.
  - `addMember(groupId, itemId)` (no duplicates) and `removeMember(groupId, itemId)`.
  - `addPerson(name): Promise<void>` (the caller checks duplicates against Home and the existing names).
- **`useUsage` returns:**
  - `{ byItem, byGroup: Map<string, GroupUsage>, isLoading }`.
  - `GroupUsage = { group; name; perMonth; source; stock; toBuy; options: (ItemOption & { perBase })[] }`.
  - `ItemOption = { item_id; name; unit; holds; unitCents }`.
  - It now also queries the active groups, the members and `LAST_PRICE_SQL`.
  - An item in any active group gets `toBuy: null` in `byItem`, and its `explain` reads `Bought as part of {names}`.
- **`listRepo`:**
  - `makeList` takes the new suggestion shape.
  - `INSERT` writes `group_id`.
  - `addGroupToList(groupId, quantity, ticked)` adds a hand-added group entry (one per group).
