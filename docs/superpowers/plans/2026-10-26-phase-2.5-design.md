# Phase 2.5: Design Restyle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every existing screen uses one dark/light theme from DESIGN_SPEC. Items get a fixed category list (plus the owner's own) with icons and filter chips.

**Architecture:**
- `src/theme/` holds the tokens and a `useTheme()` hook built on `useColorScheme()`.
- `src/categories/` holds the pure category rules (tested) and a tiny repo.
- `src/components/` holds six reusable pieces.
- Screens keep their data logic. Only their look and the category picker change.

**Tech Stack:** The phase 2 stack plus `@expo/vector-icons` (bundled with SDK 58 as `^15.0.2`, JS-only on `expo-font`, so no dev-client rebuild).

**Spec:** [docs/superpowers/specs/2026-10-26-design-restyle-design.md](../specs/2026-10-26-design-restyle-design.md), visual source [DESIGN_SPEC.md](../../../DESIGN_SPEC.md), approved mockup `.superpowers/brainstorm/2332-1793027980/content/stock-screens.html`.

## Global Constraints

- Colour tokens exactly as DESIGN_SPEC section 2. Dark: bg `#0F1A14`, surface `#17251D`, surfaceRaised `#1F3126`, border `#2C4535`, textPrimary `#EEF5EF`, textSecondary `#A9BDB0`, primary `#7FB685`, onPrimary `#0F1A14`, accent `#F59E2B`, positive `#7FB685`, warning `#F2C14E`, danger `#E5655E`. Light: bg `#F4F7F3`, surface `#FFFFFF`, surfaceRaised `#EAF1EB`, border `#D3E0D5`, textPrimary `#12201A`, textSecondary `#4A5F52`, primary `#2F7A47`, onPrimary `#FFFFFF`, accent `#D9780B`, positive `#2F7A47`, warning `#B27A00`, danger `#C0392B`.
- Card fill: dark `rgba(23,37,29,0.92)` with no shadow. Light `#FFFFFF` (solid) with shadow `0 2px 8px rgba(0,0,0,0.06)` (`boxShadow` style). Card border 1px `border`, radius 20.
- `radius = { card: 20, button: 16, chip: 999, bar: 24 }`, `spacing = [4, 8, 12, 16, 24, 32]`, screen side padding 16.
- Type: title 24, section 18, body 14–16, caption 12. Numbers 16+ semi-bold with `fontVariant: ['tabular-nums']`.
- Touch targets 48×48 or larger. No blur. No accent-coloured element on any screen this phase.
- No hex or `rgba(` colour literal in `src/app` or `src/components`. Only `src/theme` holds colours.
- Built-in categories, in order: `Pantry, Fridge, Freezer, Meat, Fruit & veg, Cleaning, Toiletries, Other`.
- `Link asChild` children get a single style object, never an array (`StyleSheet.flatten` if combining).
- No tab bar, no Stock-screen steppers, no delete, no Scan (owner decisions).
- Owner commands in PowerShell use `npx.cmd`.

## Review Focus

1. **Error text on raised surfaces:** `danger` on dark `surfaceRaised` is 4.17:1, below 4.5. Error text must sit on `bg` or the card, never inside an input pill. → Task 1 test `contrast pairs pass 4.5`, which covers danger on bg and surface only.
2. **Old categories with other capitals:** "meat" or " Pantry " typed in phase 1 must land in Meat and Pantry, and "dairy" must land in Other. → Task 2 test `resolveCategory matches built-ins ignoring case`.
3. **Duplicate custom category:** adding "pantry" or an existing custom name in other capitals must be refused with a message, not create a second chip. → Task 2 test `validateNewCategory refuses duplicates`.
4. **Filter hides rows but Save keeps them:** in Stock-take, counting Rice under Pantry, switching to Fridge and saving must still save Rice. → Task 5 manual check, plus the screen keeps `entries` keyed by item id across filters (it already does).
5. **Theme switch while open:** changing Android dark mode with the app open must restyle every screen with no restart, including the header. → Task 7 phone check 2.

### Task 2: Category rules, table and repo

**Files:**
- Create: `eekhoring/src/categories/categoryRules.ts`, `eekhoring/src/categories/categoryRepo.ts`
- Modify: `eekhoring/src/db/schema.ts` (add `categories = new Table({ name: column.text, created_at: column.text })` to `AppSchema`)
- Test: `eekhoring/src/categories/categoryRules.test.ts`

**Interfaces:**
- Produces:
  - `BUILT_IN: { name: string; icon: IconName }[]`, in the Global Constraints order. `type IconName = string` (a `MaterialCommunityIcons` glyph name; the builder picks the icons). Custom categories use icon `'tag-outline'`.
  - `orderedCategories(custom: string[]): { name: string; icon: string }[]`: built-ins without Other, then the custom names A–Z (case-insensitive), then Other.
  - `resolveCategory(raw: string, custom: string[]): string`: trims, matches a built-in or custom name ignoring case, and returns its canonical spelling. Otherwise returns `'Other'`.
  - `validateNewCategory(raw: string, custom: string[]): { ok: true; name: string } | { ok: false; error: string }`
  - `groupByCategory<T extends { category: string }>(rows: T[], custom: string[], only: string | null): { title: string; icon: string; data: T[] }[]`: sections in `orderedCategories` order, only non-empty ones. Rows are resolved with `resolveCategory`. When `only` isn't null, only that section is returned.
  - `categoryRepo.ts`: `CUSTOM_CATEGORIES_SQL = 'SELECT name FROM categories ORDER BY name COLLATE NOCASE'`, `addCategory(name: string): Promise<void>` (inserts `randomUUID()`, name, ISO `created_at`).

- [ ] **Step 1: Write the failing tests** in `categoryRules.test.ts`:

```ts
import { groupByCategory, orderedCategories, resolveCategory, validateNewCategory } from './categoryRules';

test('orderedCategories puts custom between built-ins and Other', () => {
  expect(orderedCategories(['baby', 'Alcohol']).map((c) => c.name)).toEqual([
    'Pantry', 'Fridge', 'Freezer', 'Meat', 'Fruit & veg', 'Cleaning', 'Toiletries', 'Alcohol', 'baby', 'Other',
  ]);
});

test('resolveCategory matches built-ins ignoring case', () => {
  expect(resolveCategory(' meat ', [])).toBe('Meat');
  expect(resolveCategory('fruit & VEG', [])).toBe('Fruit & veg');
  expect(resolveCategory('alcohol', ['Alcohol'])).toBe('Alcohol');
  expect(resolveCategory('dairy', [])).toBe('Other');
  expect(resolveCategory('', [])).toBe('Other');
});

test('validateNewCategory refuses duplicates', () => {
  expect(validateNewCategory('  Baby  ', [])).toEqual({ ok: true, name: 'Baby' });
  expect(validateNewCategory('pantry', [])).toEqual({ ok: false, error: 'Pantry already exists' });
  expect(validateNewCategory('ALCOHOL', ['Alcohol'])).toEqual({ ok: false, error: 'Alcohol already exists' });
  expect(validateNewCategory('  ', [])).toEqual({ ok: false, error: 'Give the category a name' });
});

test('groupByCategory orders sections and filters', () => {
  const rows = [{ id: '1', category: 'Other' }, { id: '2', category: 'meat' }, { id: '3', category: 'Pantry' }];
  expect(groupByCategory(rows, [], null).map((s) => [s.title, s.data.map((r) => r.id)])).toEqual([
    ['Pantry', ['3']], ['Meat', ['2']], ['Other', ['1']],
  ]);
  expect(groupByCategory(rows, [], 'Meat').map((s) => s.title)).toEqual(['Meat']);
});
```

### Task 3: Components

**Files:**
- Run: `npx expo install @expo/vector-icons`. Expected: `^15.x` added to `package.json`.

**Interfaces:**
- Consumes: `useTheme`, `radius`, `spacing`, `font` (Task 1); `orderedCategories` (Task 2).
- Produces:
  - `Screen({ children, padded = true })`: a `View` with `flex: 1`, `bg`, and 16 side padding.
  - `ItemCard({ name, icon, meta, right, muted? }: { name: string; icon: string; meta: string; right: ReactNode; muted?: boolean })`: card styling, a 44×44 icon tile on `surfaceRaised` with a `MaterialCommunityIcons` glyph in `primary`, the name at 16 semi-bold, the meta line as a caption in `textSecondary`, and `right` on the right. `muted` dims the name (archived). It's a plain `View`, and callers wrap it in `Pressable`/`Link`.
  - `StockNumber({ quantity, unit }: { quantity: number | null; unit: string })`: 20 bold tabular `textPrimary` over a caption reading `{unit} left`. Shows `not counted` in caption style when `quantity` is null.
  - `QuantityStepper({ value, placeholder, onMinus, onPlus, onChangeText, label, invalid })`: a pill on `surfaceRaised` with 48×48 − / + buttons (`accessibilityLabel` `Less {label}` / `More {label}`) and a 64-wide centred decimal `TextInput`. The placeholder shows in `textSecondary`. When `invalid`, the pill border is `danger`.
  - `CategoryChips({ categories, selected, onSelect, includeAll = true, trailing? }: { categories: { name: string }[]; selected: string | null; onSelect: (name: string | null) => void; includeAll?: boolean; trailing?: ReactNode })`: a horizontal `ScrollView` of pills with min height 48. Selected chips are `primary`/`onPrimary`, others `surfaceRaised`/`textPrimary`. "All" maps to `null`. `trailing` renders after the last chip (used for "+ New category").
  - `FrequencyToggle({ value, onChange }: { value: BuyMode; onChange: (v: BuyMode) => void })`: a segmented "Monthly | As needed" control with `accessibilityRole="radio"`.
  - `PrimaryButton({ label, onPress, variant = 'filled', disabled? })`: a `Pressable` 56 tall with radius 16. `filled` is `primary`/`onPrimary`. `outline` is a 2px `primary` border with `primary` text. Each variant has one style object (safe inside `Link asChild`). Spreads extra props onto the `Pressable` so `Link asChild` can pass `onPress` and `href` (React 19: no `forwardRef` needed).
